# Codex Usage Dashboard · Apple 设计语言升级方案

## 设计判断

目标不是把页面仿造成 macOS 窗口，而是把 Apple 的设计原则用于数据产品：内容优先、层级清楚、交互直接、材质克制、动效有因果。最终方向定义为 **Apple-grade analytical instrument**——像一台精密、安静、可信的分析仪器。

半透明材质只用于侧栏、筛选工具条、浮层和悬停反馈。额度、模型、趋势等核心数据面板保持清晰的实体表面，避免玻璃效果降低图表对比度。颜色承担语义，不单独承担信息表达。

## 首页信息叙事

首页按用户真正的决策顺序组织：

1. **账户健康**：五小时额度、每周额度、重置时间、快照时间和数据覆盖状态。
2. **模型消耗**：各 GPT 模型的额度消耗强度、估算 Credits、输出 token/s、总 token、占比、调用数和缓存效率；这是首页最醒目的分析模块。
3. **时间变化**：筛选范围内每日或每小时 token 构成，与额度快照使用上下对齐的独立图表呈现，不共用纵轴。
4. **消耗归因**：从项目进入任务，再进入单次调用，回答“消耗发生在哪里”。
5. **异常与建议**：仅显示有数据证据的高消耗任务、缓存异常和集中度变化，不生成泛化建议。

页面首屏采用“两层焦点”：顶部保留双额度状态；其下让“GPT 模型消耗与速率”横跨内容区。常规 KPI 合并为紧凑摘要条，避免四张同权卡片抢走视觉注意力。

## 模型模块

### 默认视图：精确排行

保留当前横向排行的易读性，但升级为两条同步量尺：

- 主量尺显示 token 总量，使用绝对值和占比。
- 左侧默认显示每次调用的估算额度消耗强度，可切换为输出生成速率（token/s）；右侧独立量尺显示 token 总量。
- 行尾显示调用次数和缓存命中率。
- 排序变化使用位置过渡，数值使用短促滚动过渡。
- 颜色只区分指标语义；模型身份依靠名称、位置和直接标注，不依赖多色图例。

### 探索视图：模型效率地图

提供可切换的散点图：横轴为输出 token/s，纵轴为 token 总量，点面积为调用次数，点的描边或标签表达缓存效率。它用于发现“生成快”“总量高”“调用频繁”三类不同模式。图下保留可访问的数据表，键盘用户可以逐项浏览。

散点图不会取代排行，因为排行更适合精确比较；探索视图只用于模式发现。模型少于三个时隐藏该视图。

## 图表系统

使用 D3 构建统一的比例尺、坐标轴、刷选和提示层，不依赖装饰型图表：

- **Token 时间线**：输入、缓存输入、输出堆叠面积或柱形图；支持悬停十字线和区间刷选。
- **额度历史**：五小时与每周额度分别使用阶梯线，断档明确显示，不对缺失快照插值。
- **模型 × 项目热力图**：发现模型成本集中在哪些项目；单元格同时提供数值标签或 tooltip。
- **任务异常点图**：横轴为 token 总量，点的第二编码为缓存命中率，直接标出少数离群任务。
- **构成图**：优先使用 100% 堆叠条；只在类别很少且比较单一整体时使用环图。

所有图表遵循四项规则：数据标记最醒目、轴线退后、标签靠近数据、同一指标始终使用同一语义颜色。窄屏不缩小到难以阅读，而是减少刻度、调整排列，并允许图表内部横向浏览。

## 视觉系统

### 字体与数字

- UI 使用系统字体栈 `-apple-system, BlinkMacSystemFont, "SF Pro Display", "PingFang SC", sans-serif`。
- token、百分比、时间和模型版本使用 `SF Mono` 回退栈并开启等宽数字。
- 页面标题 32–36px，模块标题 18–20px，正文不低于 13px，关键数据 28–40px。
- 减少全大写和 9–10px 微型标签；层级主要由字号、字重和留白建立。

### 色彩与材质

- 背景采用中性深灰蓝，降低现有页面的蓝色染色感。
- 主强调色使用克制的系统蓝；警戒色只在额度紧张和异常时出现。
- 缓存输入、非缓存输入、输出和推理输出具有稳定的语义色，并辅以纹理、标签或形状。
- 浅色和深色主题都使用语义 token，并为提高对比度模式保留独立值。
- 侧栏和筛选栏可使用轻度半透明与背景模糊；数据卡片使用实体背景、细分隔线和极轻阴影。

### 布局

- 采用 8pt 基准：8 / 12 / 16 / 24 / 32 / 48。
- 内容最大宽度约 1500–1600px，宽屏扩大图表绘图区，不无限拉长文字。
- 主要模块圆角 16–20px，控件圆角 10–12px；减少每个区域都套边框的视觉噪声。
- 筛选栏在滚动时保持可见，并实时显示当前范围摘要。

## 动效规范

动效用于解释状态变化，不作为背景装饰：

- 控件反馈 120–180ms；筛选和图表更新 180–240ms；抽屉和大布局 240–320ms。
- 排序采用 FLIP 位置过渡，让模型行自然移动到新位置。
- 筛选时复用现有图形元素，平滑更新尺度和标记；避免每次重新播放整页入场动画。
- tooltip 贴近指针或焦点，使用轻微淡入与位移；十字线无弹性效果。
- 页面首次打开只让最重要的数据做一次短入场，避免所有卡片依次飞入。
- 完整支持 `prefers-reduced-motion`，关闭动效时仍保留清楚的状态反馈。

## 专业数据洞察

首页只呈现可以行动的结论：

- **总量领跑模型**：当前范围内 token 总量最高的模型及其占比。
- **额度强度最高模型**：按估算 Credits/调用排名，解释为什么低 Token 总量仍可能快速消耗额度。
- **生成最快模型**：按输出 token/s 排名，并同时显示有效测速调用数，防止小样本误导。
- **高频模型**：调用次数最高，区分“调用多”和“每次重”。
- **缓存效率**：按模型和项目展示缓存输入占比，低样本量标注为证据不足。
- **集中度**：Top 1 / Top 3 项目或任务占总消耗比例。
- **异常任务**：相对同类任务显著偏高时才提示，并说明比较基线。

额度消耗强度和生成速度必须拆开：额度强度定义为 `官方 Credit 费率估算值 / 调用次数`；生成速度定义为 `可测速调用的输出 token / 模型生成持续秒数`，显示为 token/s。没有可靠持续时间时速度显示“不可用”，不能使用整个任务耗时，因为工具调用和用户等待会污染模型生成速度。

## Skill 组合与执行顺序

正式重构按以下顺序调用能力：

1. `hig-foundations`：检查颜色、排版、布局、暗色模式、材质和可访问性是否符合 Apple HIG 原则。
2. `impeccable`：重整信息层级、密度、组件状态和整体完成度。
3. `d3-data-visualization`：实现时间线、效率地图、热力图、刷选、tooltip 和响应式坐标轴。
4. `design-motion-principles`：设计并审查排序、筛选、抽屉和图表过渡。
5. 浏览器验收：桌面、窄屏、键盘、减少动态效果、深浅主题、空状态和大数据量。

这四层能力已经足够覆盖本项目。继续堆叠同类技能会产生重复约束，降低设计一致性。

## 下一版验收标准

- 首屏 3 秒内能回答：额度还剩多少、哪个模型消耗最多、当前数据覆盖到什么时候。
- 用户可以在 2 次交互内从模型或项目进入高消耗任务。
- 图表无需依赖图例就能理解主要编码，所有精确值均可通过直接标签、焦点或 tooltip 获取。
- 深色、浅色和提高对比度模式下，文本、轴线、焦点和数据标记均可辨认。
- 关闭动效后功能与信息不缺失；开启动效时没有持续循环的装饰动画。
- 缺失额度、断档快照、小样本和合成数据都被明确标注，不推断不存在的数据。
